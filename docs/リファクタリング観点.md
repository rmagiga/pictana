# Pictana リファクタリング観点チェックリスト

## 基本方針

- Dart / Flutter は最新 Stable を使用する
- Dart 3 モダン構文を使用する
  - Records
  - Pattern Matching
  - sealed class
  - switch expression
  - class modifiers (`final`, `base`, `interface`)
- Deprecated API を排除する
- null safety を厳格に維持する
- Freezed / Riverpod Generator / Drift によるコード生成を前提にする
- 同期 I/O を禁止する
- UI スレッドブロックを禁止する
- 巨大画像処理は Isolate / 遅延ロード前提で設計する

---

# 1. アーキテクチャ

## レイヤ依存

- `Presentation -> Application -> Domain -> Infrastructure` を厳守する
- Domain 層で Flutter / Drift / Platform API を参照しない
- Infrastructure を UI から直接参照しない
- Repository Interface は Domain/Application 側に配置する
- DTO と Entity を分離する
- EntryId によるパス抽象化を維持する

---

## 責務分離

- 1クラス1責務を維持する
- god class / god provider を排除する
- UseCase の責務を単一化する
- Widget にビジネスロジックを持たせない
- UI 層で DB / FileSystem を直接操作しない
- Repository に複数責務を持たせない

---

# 2. Riverpod

## Provider 設計
- Repository 系、またはアプリ全体で単一のライフサイクルを持つもののみ `@Riverpod(keepAlive: true)` を使用する
- 画面状態、UIロジックを持つ Notifier はデフォルト（autoDispose）の挙動を維持する
- 副作用（データ更新等）を実行した後は、手動で `state = ...` を作らず、`ref.invalidate()` 等を用いて宣言的にデータを再取得・再生成する
- rebuild 範囲を最小化する（Consumerの局所化）
- select による部分監視を利用する
- Provider 内で同期重処理を行わない

---

## 状態管理

- sealed class による状態管理を使用する
- AsyncValue の分岐重複を排除する
- switch expression による exhaustiveness を利用する
- nullable 状態を乱用しない
- UI状態とドメイン状態を分離する

---

# 3. パフォーマンス

## 画像処理

- 巨大 Bitmap 生成を防止する
- サムネイル生成を遅延化する
- decode サイズを制御する
- 不要な image decode を排除する
- メモリ保持画像数を制限する
- viewport 外画像を即時破棄する
- キャッシュサイズを制限する

---

## Isolate / 非同期

- 重い画像処理を Isolate 化する
- 同期 File I/O を禁止する
- DB重処理を UI isolate で実行しない
- dispose 後更新を防止する
- race condition を排除する
- unawaited future を明示する
- stream close 漏れを防止する

---

## SQLite / Drift

- N+1 Query を排除する
- SELECT * を禁止する
- index を適切に設計する
- batch insert/update を利用する
- transaction 範囲を最小化する
- watch query の監視範囲を最適化する
- DB Stream の監視リークを防止する

---

# 4. Android SAF / 外部ストレージ

## SAF
- `DocumentFile.listFiles()` を禁止する（パフォーマンス劣化防止）
- `ContentResolver.query()` を使用し、クエリ処理自体も非同期/バックグラウンドで実行する
- URI permission（`takePersistableUriPermission`）を適切に保持・管理する
- OS側の永続URI保持上限（一般に128個）を考慮し、不要になったURIパーミッションは明示的に解放する
- URI 解決失敗時（ファイル削除、メディア再スキャン時など）の復旧・再選択処理を実装する

---

## 外部ストレージ切断

- USB切断時クラッシュを防止する
- 切断時に画面遷移を発生させない
- インライン通知を使用する
- キャッシュ画像表示を維持する
- バックグラウンドリトライを実装する
- 無限リトライを防止する

---

# 5. エラーハンドリング

- OS例外を Domain例外へ変換する
- Platform例外を UI へ露出しない
- Recoverable / Fatal を分離する
- stacktrace を保持する
- 例外握り潰しを禁止する
- ログ用途例外と表示用途例外を分離する

---

# 6. Flutter UI

## Widget 設計

- Widget を小粒化する
- StatelessWidget を優先する
- build 内重処理を禁止する
- const constructor を利用する
- UI共通部品を抽出する

---

## 描画最適化

- RepaintBoundary を適切に使用する
- List/Grid key を適切に設定する
- nested scroll を最小化する
- rebuild 範囲を局所化する
- layout pass の多重発生を防止する

---

# 7. コード品質

## 重複排除

- Duplicate Code を排除する
- copy-paste 実装を禁止する
- 共通 mapper / extension を抽出する
- 条件分岐重複を排除する

---

## 可読性

- 長大メソッドを分割する
- 深いネストを排除する
- bool 引数多用を禁止する
- magic number / string を定数化する
- 命名を責務ベースに統一する

---

## Null安全

- nullable を最小化する
- `!` 演算子使用を制限する
- null を状態表現として乱用しない
- sealed class に状態を集約する

---

## Dart 3 モダン化

- tuple package を Records に置換する
- if-else 連鎖を Pattern Matching に置換する
- 状態分岐を switch expression 化する
- enum 的状態を sealed class 化する
- 不要な Freezed Union を削減する

---

# 8. プログラミング原則

## SOLID

- SRP に基づき責務を単一化する
- OCP に基づき Storage / Cache / ImageFormat 拡張を閉鎖的に設計する
- ISP に基づき巨大 Repository Interface を分割する
- DIP に基づき Drift / SAF / FileSystem API を抽象化する

---

## DRY

- 重複 AsyncValue 分岐を統一する
- 重複エラーハンドリングを統一する
- 共通 Widget / extension / mapper を抽出する
- SAF URI 解決処理を統一する

---

## KISS

- 小規模処理への過剰 abstraction を排除する
- 不要な generic abstraction を作成しない
- 不要な UseCase 分割を避ける

---

## YAGNI

- 未使用 abstraction を追加しない
- 使用予定のみの Interface を作成しない
- 実要件が存在しないキャッシュ戦略を実装しない

---

## Composition over Inheritance

- Widget 継承より composition を優先する
- mixin の乱用を防止する
- base class 肥大化を防止する

---

## Immutable Design

- Freezed による immutable state を維持する
- Provider state を immutable にする
- copyWith ベースで状態変更を行う

---

## Fail Fast

- 無効 URI を早期検出する
- Storage切断を即時検知する
- DB不整合を早期検出する
- 不正状態を nullable 放置しない

---

## Tell, Don't Ask

- 状態判定ロジックを Entity / Domain に集約する
- 条件分岐中心コードをメソッド委譲へ置換する

---

## Separation of Concerns

- UI / 状態管理 / DB / FileSystem / キャッシュ責務を分離する
- Platform依存処理を Infrastructure に閉じ込める

---

## Defensive Programming

- 外部ストレージ切断を常時考慮する
- URI 無効化を常時考慮する
- 画像破損を考慮する
- async cancel race を考慮する

---

- エラー系テストを実装する
