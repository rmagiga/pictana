# 整理モード 設計仕様書

## 1. 概要
本仕様書は、画像閲覧・管理アプリ「Pictana（ピク棚）」における**整理モード（Selection Mode）**の設計方針および仕様を定義する。

### 1.1 設計思想
通常閲覧時の快適な操作性（没入感・高速スクロール）と、ファイル管理時の安全性（誤操作防止・確実な処理）を両立するため、**「通常閲覧モード」と「整理モード」を明確に分離**する。
また、Android SAF (Storage Access Framework) および Windows ファイルシステムの差異を Infrastructure 層で完全に隠蔽し、Domain/Application 層からは抽象化されたインターフェースを通じて安全に操作できる DDD 準拠の構造とする。

## 2. アーキテクチャ設計

### 2.1 依存方向とレイヤー構造
DDD（Domain-Driven Design）寄り Clean Architecture に基づき、整理操作ロジックを分離する。

```text
[Presentation] (Widget, Selection Riverpod Provider)
      ↓
[Application]  (DeleteImagesUseCase, MoveImagesUseCase, etc.)
      ↓
[Domain]       (ImageRepository Interface, EntryId Value Object)
      ↑
[Infrastructure] (Drift DB, Android SAF / Windows FileSystem API)
```

### 2.2 Domain層の定義

#### 2.2.1 識別子の抽象化 (`EntryId`)
整理対象の画像は、プラットフォームごとに異なる識別子を持つが、Domain 層では `EntryId` Value Object で抽象化する。
- **Android**: `content://` で始まる URI 文字列
- **Windows**: 絶対ファイルパス文字列

#### 2.2.2 `ImageRepository` インターフェースの拡張
整理モードのサポートに伴い、[ImageRepository](file:///d:/work/optrig/lib/domain/repositories/image_repository.dart) に以下のメソッドを定義する。

```dart
/// 画像の物理削除
/// Android SAF または Windows ファイルシステム上でファイルを物理削除する。
/// 失敗時は [StorageDisconnected] または [PermissionDenied] をスローする。
Future<void> deleteImages(List<EntryId> entryIds);

/// 画像の移動 (Copy + Delete 方式)
/// 異なるフォルダへ画像を移動する。進捗状況を [onProgress] で通知する。
/// [cancellationToken] を指定することで、処理を途中で安全に中断できる。
Future<void> moveImages({
  required List<EntryId> entryIds,
  required FolderEntry destination,
  void Function(double progress)? onProgress,
  CancellationToken? cancellationToken,
});

/// 画像のコピー
/// 異なるフォルダへ画像をコピーする。進捗状況を [onProgress] で通知する。
/// [cancellationToken] を指定することで、処理を途中で安全に中断できる。
Future<void> copyImages({
  required List<EntryId> entryIds,
  required FolderEntry destination,
  void Function(double progress)? onProgress,
  CancellationToken? cancellationToken,
});

/// お気に入り状態の一括更新
/// データベースおよびメタデータ上のお気に入り状態を更新する。
Future<void> updateFavoriteStatus({
  required List<EntryId> entryIds,
  required bool isFavorite,
});
```

### 2.3 Application層 (UseCase) の定義
UseCase は、ファイル操作（Repository）とローカルデータベース（Drift DB）の同期処理をアトミックに制御する役割を担う。

#### 2.3.1 `DeleteImagesUseCase`
- 選択された `List<EntryId>` を物理削除し、Drift DB のレコードも削除する。
- **誤操作防止のための安全確認**:
  - 削除対象が **大量（例: 20枚以上）** である場合、即時仮削除には移らず、実行前に「N件の画像を物理削除しますか？」の確認ダイアログを表示する。20枚未満の場合は確認なしで即座に仮削除とする。
- **即時物理削除による誤操作を防ぐため、遅延物理削除（Undo 猶予）を制御する。**
- 具体的なフロー：
  1. UI側で対象画像を即座に非表示（仮削除）にする（Riverpod 状態での除外）。
     - クラッシュやアプリの強制終了時は、物理削除が実行されず画像が復帰する挙動を許容する（安全性の優先）。
  2. スナックバーで「N件の画像を削除しました」および「元に戻す」ボタンを表示（5秒間）。
     - 5秒の猶予中にさらに別の削除が発生した場合は、スナックバーの表示を「M件の画像を削除しました（合計O件）」のようにマージし、猶予タイマーをリセットする。
  3. 「元に戻す」が押されなかった場合、本 UseCase が `ImageRepository.deleteImages` を呼び出し物理削除を実行。成功後、Drift DB からレコードを削除する。
  4. 物理削除中にエラーが発生した場合、インライン通知を表示し、画像を一覧に復帰させる。

#### 2.3.2 `MoveImagesUseCase` / `CopyImagesUseCase`
- 選択された画像を別フォルダへ移動またはコピーする。
- **DB同期のタイミング**:
  - 移動の場合: コピー先に新規ファイルを生成 → コピー先の DB レコードを追加 → コピー元の物理ファイルを削除 → コピー元の DB レコードを削除。
  - コピーの場合: コピー先に新規ファイルを生成 → コピー先の DB レコードを追加（メタデータ等のインデックス化）。
- **キャンセル対応**:
  - `CancellationToken` をサポートし、ユーザーが途中で中断した場合は、コピー途中の不完全なファイルを削除するなどのクリーンアップを行う。
- 進捗率 (0.0 〜 1.0) を Stream やコールバック経由で UI (Presentation層) へ中継する。

#### 2.3.3 `ToggleFavoriteUseCase`
- 選択された画像群のお気に入り状態を一括でトグルし、Drift DB のレコードを更新する。

## 3. UI・操作仕様 (Presentation層)

### 3.1 モードの遷移

#### 通常閲覧モードから整理モードへの遷移条件
1. **サムネイルの長押し**: 長押しされた画像を最初の選択アイテムとして整理モードを起動。
2. **画面上部（AppBar）の「選択」メニュー**: 空の選択状態から整理モードを起動。
3. **キーボードショートカット (Desktop)**: `Ctrl + A` (全選択)、または `Space` キー (現在のフォーカス画像を長押し相当で選択)。

#### 整理モード中の個別サムネイル操作
1. **タップ**: 選択状態をトグルする（詳細画面には遷移しない）。
2. **長押し**: 整理モードを維持したまま、対象画像の「**クイックプレビュー（ポップアップ表示）**」を提供する。これにより、似た画像を見分けるために整理モードを一旦解除する手間を防ぐ。

#### 整理モードから通常閲覧モードへの遷移（解除）条件
1. **AppBar の「←（戻る）」または「キャンセル」ボタンのタップ**
2. **物理的な戻る操作 (Android バックジェスチャー)**
3. **キーボードの `Esc` キー (Desktop)**
4. **一括操作の完了後 (操作の性質に応じて自動解除または選択クリア)**
   - **現在地から画像が消失する操作 (物理削除、フォルダ移動など)**: 処理完了後に自動で整理モードを解除する。
   - **現在地に画像が残る操作 (コピー、お気に入り登録など)**: 処理完了後も整理モードを維持し、選択状態のみをクリア（または選択維持）する。

### 3.2 状態管理 (Riverpod)
整理モードの状態管理には、`riverpod_generator` を使用して以下の Provider を実装する。

- `isSelectionModeProvider`: 整理モードのON/OFF状態を管理する (`Notifier<bool>`)。
- `gallerySelectionProvider`: 選択されている画像の `EntryId` のセットを保持する Notifier (`Notifier<Set<EntryId>>`)。
  - メソッド：`toggle(EntryId id)`, `selectAll(List<EntryId> ids)`, `clear()`
- `lastSelectedEntryIdProvider`: 範囲選択（Shift + クリック）の起点（アンカー）となる `EntryId` を保持する Provider (`Notifier<EntryId?>`)。
  - 範囲選択が行われた際、この起点から新たにクリックされた画像までのインデックス（表示順）を計算し、一括で `gallerySelectionProvider` に追加する。

### 3.3 仮想スクロールとセル描画の最適化
- 大量画像（10,000枚規模）でのパフォーマンス（60fps）を維持するため、**サムネイル Widget 自身に選択状態を持たせない**。
- `extended_image` や `SliverGrid` 内の各サムネイルセルは、`ref.watch(gallerySelectionProvider.select((set) => set.contains(entryId)))` を使用して、自身が選択されているかどうかのみを監視（Rebuild の最小化）する。

### 3.4 整理モード時の UI レイアウト

#### 3.4.1 AppBar (ヘッダー)
- 通常時の検索・ソートなどのメニューを非表示にし、以下を表示する：
  - `←`（解除ボタン）
  - 「N 件選択中」の件数表示
  - `[全選択]` ボタン
  - `[選択解除]` ボタン (1件以上選択されている場合)

#### 3.4.2 サムネイルグリッドのオーバーレイ
- 選択されたセルには以下の視覚的フィードバックを提供する：
  - **チェックマークの表示**: セルの右上または左上にチェックアイコン（テーマカラー）を表示。
    - アスペクト比により画像が縮小表示（`BoxFit.contain`）されている場合、余白ではなく **画像の実描画領域の四隅** に合わせてチェックマークやオーバーレイを配置し、視覚的な選択対象を明確にする。
  - **半透明のオーバーレイ**: 画像の上に半透明（例: `Colors.black38` またはテーマカラーの半透明）のレイヤーを重ねる。
  - **ボーダー（境界線）**: セルの周囲（または画像の実領域の周囲）に太めのボーダーを強調表示する。

#### 3.4.3 下部アクションツールバー (Bottom Action Bar)
画面下部からスライドインで表示されるツールバー。
- **配置とレイアウト競合の回避**:
  - 削除実行時の Undo スナックバーが表示される際、下部ツールバーと重なってボタンが隠れないよう、スナックバーは **ツールバーの上部** に浮かせて表示（フローティング）するか、ツールバー内にインラインで Undo ボタンを統合する。
- **削除 (Delete)**: ゴミ箱アイコン。インメモリでの Undo スナックバーを伴う削除。
- **移動 (Move)**: フォルダ移動アイコン。宛先選択ダイアログを表示。
  - **宛先選択のUX要件**: ダイアログ内には、よく使う/最近使ったフォルダの「クイックアクセスリスト」を表示する。また、その場で「新規フォルダ作成」ができるUIを提供する。
- **コピー (Copy)**: コピーアイコン。宛先選択ダイアログを表示。
  - **宛先選択のUX要件**: 移動と同様に、「クイックアクセスリスト」および「新規フォルダ作成」機能を提供する。
- **お気に入り (Favorite)**: 星アイコン。選択された画像の一括お気に入り登録/解除。
  - **混在時の挙動**: 選択画像にお気に入り登録済・未登録が混在する場合、アイコンは「半点灯」状態とする。タップ時の挙動は **「1回目で全てON（お気に入り登録）」** とし、全てONの状態から再度タップされた場合のみ **「全てOFF（解除）」** とする（個別トグルによる意図しない解除を防ぐ）。
- **共有 (Share - モバイル推奨)**: 共有アイコン。OS標準の共有シートを呼び出す。

### 3.5 処理中の二重操作防止 (UIロック)
- コピー、移動、削除などの時間のかかる一括処理を実行している間は、画面全体に半透明のモーダルバリア（ローディングインジケータ付き）を表示し、ユーザーによる以下の操作を完全にブロックする。
  - 画像サムネイルのタップ・長押し
  - 画面遷移（戻る操作、フォルダ切り替えなど）
  - 別の一括アクションのトリガー
- **進捗フィードバックの具体化**:
  - モーダルバリアまたはダイアログ内には、進行状況ゲージに加え、「**○ / N 枚目**」といった詳細な処理数、および「**現在処理中のファイル名**（プライバシー考慮のため末尾をマスク）」を表示する。
  - ユーザーが処理の中断を行えるよう、「**キャンセル**」ボタンを常に表示する。
- 処理が完了、またはキャンセル（中断）された後、モーダルバリアを自動で解除する。

## 4. プラットフォーム固有の実装 (Infrastructure層)

### 4.1 Android (SAF / Kotlin)

#### 4.1.1 削除処理
- `ContentResolver` を経由し、`DocumentsContract.deleteDocument(contentResolver, documentUri)` を呼び出して物理削除を行う。
- 大量削除時、メインスレッドをブロックしないよう Kotlin 側で `Dispatchers.IO` コルーチンを用いて非同期実行する。

#### 4.1.2 移動・コピー処理 (Copy + Delete)
- Android SAF 環境下では、異なるストレージルート間（内部ストレージ ↔ USB OTGなど）の `renameTo` や `moveDocument` は OS 制限により失敗する。
- したがって、**「宛先へのストリームコピー → 成功後に元ファイルの削除」の二段階（Copy + Delete）処理**を基本とする。
- コピー処理は Kotlin 側でバッファを用いて効率的に行い、MethodChannel または EventChannel を通じて「○/N 件完了」およびパーセンテージを進捗率として Dart 側に通知する。

#### 4.1.3 例外の厳格なマッピング
I/O 処理中に発生する OS 固有の例外は、以下のように Domain 例外へ変換し、Presentation/Application 層へ漏らさない。
- `SecurityException` (権限喪失) → `PermissionDenied`
- `FileNotFoundException` / `IOException` → `StorageDisconnected` (USB切断など)

### 4.2 Windows (dart:io)

#### 4.2.1 削除処理
- `dart:io` の `File(filePath).delete()` を呼び出して物理削除を行う。
- 同期 I/O は UI スレッドをブロックするため厳禁とし、必ず非同期メソッド (`delete()`) を使用する。

#### 4.2.2 移動・コピー処理
- 同一ボリューム内であれば `File(filePath).rename()` を試みる。
- ボリュームをまたぐ場合（ローカル ↔ USBドライブなど）は `File.copy()` を行い、完了後に元の `File.delete()` を実行する。
- `Isolate` または非同期 API を活用し、UI スレッドをフリーズさせない。

## 5. デスクトップ (Windows) 特有の操作仕様

### 5.1 キーボードショートカット
デスクトップ環境における整理効率向上のため、以下の操作に対応する。
- **フォーカスと選択の視覚的区別**:
  - キーボードの矢印キーでグリッド上を移動する際、現在フォーカスがあるセル（操作対象）は「青い点線枠」、選択されているセル（チェック済み）は「テーマカラーの実線枠＋チェックマーク」のように表現を明確に分け、両者が重なった場合は「二重の枠線」で表現する。
- `Space` キー: 現在フォーカスがある画像の選択状態を反転（トグル）する。
- `Delete` キー: 選択された画像の一括削除（スナックバーの Undo 付き）。
- `Ctrl + A`: 現在表示されている画像（検索・フィルター適用後）の全選択。
  - **全選択時のパフォーマンス**: 10,000枚規模の一括処理でUIがフリーズしないよう、状態更新をバックグラウンド（Isolate等）でバッチ処理するか、一時的に「全選択中...」の軽量インジケータを挟む。
- `Esc` キー: 整理モードの解除。
- `Shift + クリック`: 範囲選択（起点画像から終点画像までの一括選択）。
  - **選択状態の連動**: 単純な反転（トグル）ではなく、**起点の状態に追従**する（起点を「選択」したなら範囲内はすべて強制選択、起点を「解除」したなら範囲内はすべて強制解除）。

### 5.2 マウス・トラックパッド操作
- **ドラッグ範囲選択**: マウスのドラッグ操作によって、矩形領域内の画像を範囲選択可能とする。
  - **オートスクロール**: ドラッグ中にマウスポインターが画面の上下端に近づいた際、グリッドリストを自動でスクロールさせ、画面外の画像も連続して選択可能とする。
- **右クリックコンテキストメニュー**: 選択された画像の上で右クリックした際、削除・移動・コピー・お気に入りのアクションメニューを表示。

### 5.3 モバイル (Android) 特有の操作仕様
- **スライド連続選択**: 整理モード中、1つのサムネイルを長押し（またはタップ）した後、そのまま指を離さずにグリッド上をスライド（スワイプ）させることで、指の通った軌跡上の画像を連続して選択・選択解除できる「なぞり選択」を可能とする。
  - **なぞり中の挙動ルール**: 通過する画像を単にトグル反転させるのではなく、**「なぞり始めた最初のセルの変化」に追従**させる（選択されていないセルからスライドを開始したなら通過セルを全て「選択」にし、選択済みのセルから開始したなら全て「解除」にする）。これにより、指のブレによる意図しない反転を防ぐ。

## 6. 例外・異常系シナリオと対策 (切断対策)

### 6.1 処理中の USB / 外部ストレージ切断
移動・コピー・削除の処理中に USB ドライブや SD カードが切断された場合：
1. **即時中断とロールバック (移動の場合)**: 
   - コピー途中のファイル（壊れたファイル）が宛先に残らないよう、宛先側の不完全なファイルを削除（クリーンアップ）する。
2. **インライン通知による状況表示**:
   - `StorageDisconnected` 例外を検知した際、進捗ダイアログを閉じ、画面上部に「USB Storage が切断されました」というインラインバナーを表示する。
3. **インメモリ Undo の復帰**:
   - 削除処理中に切断が発生して削除に失敗した場合、対象画像をグリッド一覧に即座に復帰させ、エラー内容を提示する。

### 6.2 SAF 権限上限への配慮 (Android)
- 大量フォルダを管理する中で SAF の永続化 URI 権限上限（Android 11 以降は 512件）に達した場合への対策：
  - 基本設計として、個別フォルダ単位ではなく、ストレージのルートまたは親フォルダ単位での権限取得を推奨し、永続化するURI数を最小限に抑えるUX設計とする。
  - 万が一、個別フォルダの登録が重なり 512件制限に達した場合は、自動で権限を解放（`releasePersistableUriPermission`）するとバックグラウンドのインデックス化処理や画像表示で予期せぬエラーが発生するため、自動解放は行わない。
  - 代わりに、`SecurityException` を検知した際、ユーザーに不要な登録フォルダの解除を促す警告ダイアログを表示する。
